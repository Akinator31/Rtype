Audio¶

The audio library (libs/audio, namespace rtype::audio) plays the sound effects and the music of the client. Like the render library, it wraps raylib: its public headers contain no raylib type.

Class Role
AudioDevice Opens the audio output and closes it when destroyed. Only one can exist.
AudioPlayer Loads sounds and music once, plays them, and holds the music and effects volumes. 
Window window;
AudioDevice device;                                           // after the window, see below
AudioPlayer audio(device, applicationDirectory() / "assets");

const SoundId shot = audio.loadSound("sounds/shot.wav");
const MusicId stage = audio.loadMusic("music/stage1.ogg");
audio.playMusic(stage);

while (!window.shouldClose()) {
    audio.update();                                           // once per frame, for the music
    if (controls.wasPressed(Action::Shoot)) {
        audio.play(shot);
    }
}

The audio device¶

AudioDevice opens the default audio output in its constructor and closes it in its destructor (RAII). The AudioPlayer takes it as a constructor parameter: declare the player after the device, so that sounds are freed before the output closes.

No sound is not an error. On a computer without sound card, in a virtual machine or in the CI, the output cannot be opened: a warning is logged and the game keeps running silently, with every sound ignored. Audio can also be disabled on purpose:

AudioDevice device({.enabled = false});   // tests, servers, or a "no sound" option

Create it after the window

raylib's messages are redirected to the log when the Window is created. An AudioDevice created before the window prints raylib's messages about the audio output directly to the console.

Sound effects and music¶

Sound effects Music
Typical use Shots, explosions, menu sounds Background music of a stage
Loading Fully decoded in memory Streamed from the file while it plays
At the same time Several sounds, and the same sound several times One music at a time
Functions loadSound(), play() loadMusic(), playMusic(), stopMusic(), pauseMusic(), resumeMusic()

Each file is loaded once: loading the same path again returns the same handle (SoundId, MusicId), like textures in the render library. Both use the same ResourceCache, from the core library.

loadSoundAsync() and loadMusicAsync() return shared futures. Call finishPendingLoads() on the audio owner's thread each frame, then use the handle once its future is ready. Sound files are decoded on a worker; audio buffers are created on the owner thread. Pass engine.assetLoading().queue() to the player constructor to share the engine's worker with rendering. See ADR 0017.

Playing a sound several times at once¶

With raylib, playing a sound that is already playing restarts it: fast shots would cut each other. Each sound effect therefore has 4 voices, which share the same samples in memory. play() uses a free voice, or restarts the oldest one if all four are busy.

play() takes optional settings:

audio.play(explosion, {.volume = 0.8f, .pitch = 0.9f, .pan = -0.5f});
Setting Effect
volume Volume of this sound, between 0 and 1, multiplied by the effects volume.
pitch Speed and pitch: 1 is unchanged, 2 is one octave higher. Small random variations (0.9 to 1.1) keep a repeated sound from being tiresome.
pan Position from left (-1) to right (1), 0 being centred: an explosion on the left of the screen can be heard on the left.

Streaming the music¶

A music is too long to be decoded in memory at once: it is read from its file in small parts while it plays. update() reads the next part; it must be called once per frame, otherwise the music stutters, then stops.

Volumes¶

Volume Set with Applies to
Master AudioDevice::setMasterVolume() Everything
Music AudioPlayer::setMusicVolume() The music, immediately
Effects AudioPlayer::setEffectsVolume() The sound effects played from then on

All volumes are between 0 and 1, and clamped to this range. Separate music and effects volumes are one of the accessibility features: some players need the effects louder than the music to follow the game, others are disturbed by the music. In the options menu, Effects volume is changed with Left and Right.

Supported formats¶

Format Supported
WAV, OGG, MP3, QOA Yes
XM, MOD (tracker music) Yes
FLAC No: disabled in raylib's default build

WAV suits short sound effects (no decoding cost), OGG suits music (small files, good quality, free format).

Testing¶

tests/audio.cpp tests the library with audio disabled, so that the tests give the same result with or without a sound card: volumes, single device, handles of sounds loaded twice, missing files, and the state of the music. Missing files are reported even when audio is disabled, so that they are noticed on every computer.

Limits and next steps¶

  • No spatial sound beyond left-right panning. For VR, sounds positioned in 3D around the player would help; raylib does not provide it, so it would need another approach.
  • No fading between two musics: playMusic() switches at once.
  • The effects volume does not change the sounds already playing, which are short.
