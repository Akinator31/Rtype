Detailed Description

The world as a client knows it from the messages of its game, kept as the protocol says (docs/protocol/game.md, section 9.3): the parts of the snapshots, which can be lost, late or out of order, and the destructions, which are reliable.

if (const auto part = rtype::game::decodeSnapshotPart(payload)) {
world.apply(*part);
}
if (const auto destroyed = rtype::game::decodeEntitiesDestroyed(payload)) {
for (const rtype::game::RemovedEntity &removed : world.apply(*destroyed)) {
// an explosion at removed.last.x, removed.last.y if removed.cause is Killed
}
}
for (const auto &[id, entity] : world.entities()) { /* draw it */ }

  • A part older than the latest one applied is ignored; the other parts of that latest tick still apply.
  • An entity is created or updated by the parts, and only removed by ENTITIES_DESTROYED: missing from a part means its part was lost, not that it is gone.
  • The ids destroyed are remembered until the snapshots reach the tick of their destruction, so that an older part cannot bring them back.
  • The entities of a kind this version does not know are skipped.

It keeps the latest state only: drawing in the past and interpolating come on top of it. Pure: no clock, no network.
