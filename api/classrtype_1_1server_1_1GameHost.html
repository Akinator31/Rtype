Detailed Description

The network side of a game, on the network thread of an instance: its UDP socket, the sessions of its players, their slots, and the messages of the game protocol (docs/protocol/game.md).

It hands the players and their inputs to the GameThread, and sends the result of each tick to the clients.

rtype::server::GameHost host(loop, rtype::network::Address::anyIpv4(udpPort), 4, game,
{.onConnected = [&](std::uint32_t player) { link.sendPlayerConnected(player); },
.onDisconnected = [&](std::uint32_t player, auto reason) { ... }});
host.addPlayer(addPlayer); // ADD_PLAYER from the master
host.publish(result); // each tick, from the GameThread through loop.post()

  • A player gets the lowest free slot when added, and its ship when its client connects.
  • On CONNECT, the client receives ACCEPTED (its slot, the tick rate, the tick), then PLAYER_JOINED for each player connected, itself included; the others receive its PLAYER_JOINED.
  • The inputs of each INPUT go to the game, which applies each one at its tick.
  • Every 2 ticks, each client receives the snapshot in parts; every tick, the destroyed entities. They leave at once, not at the next update of the sessions: no delay, no jitter.
  • A session that closes takes the ship away, and the others receive PLAYER_LEFT.
  • The game over is sent to every client (GAME_OVER), then told to the instance with the scores; nothing is published after it.
