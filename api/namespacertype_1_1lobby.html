Detailed Description

The messages between a client and the master, in the frames of their TLS connection (docs/protocol/lobby.md, section 5).

The client and the server share them: the client writes the requests and reads the replies, the master the other way round.

// Client: HELLO may be sent at once, it waits for the end of the handshake
const rtype::lobby::HelloMessage hello{.name = "Pavel"};
connection.send(rtype::lobby::message_type::Hello, rtype::lobby::encode(hello));
// Client, in the frame handler
if (type == rtype::lobby::message_type::Welcome) {
if (const auto welcome = rtype::lobby::decodeWelcome(payload)) { playerId = welcome->playerId; }
}

The encoders throw std::invalid_argument for a value the protocol forbids. The decoders are pure and never throw: nothing for a malformed payload. Two fields are read as they come, and checked by the master afterwards, since a wrong value there is not malformed but has its own error: the version of HELLO (UNSUPPORTED_VERSION), and the names of HELLO and CREATE_GAME (INVALID_NAME, see isValidPlayerName()).
